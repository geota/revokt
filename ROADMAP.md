# Roadmap

**Current focus**: 0.1, the `Rule` model (#72, #73), then the `index.bin` reader and writer with `GenerationFiles`
(CONTRIBUTING §2).

> [!WARNING]
> revokt is pre-release and not production ready. Nothing is published yet, and the public API may change in any
> 0.x release. Binary compatibility within a major is promised from 1.0.

The spec's [§11](docs/spec/revokt-spec.md#11-milestones-and-versioning) is the normative scope of each milestone.
This page restates it in plain language and tracks progress. [`docs/dev/status.md`](docs/dev/status.md), generated by
`./gradlew specStatus`, counts the §9 fixtures implemented and reports the measured D8 gap. Inside a milestone, work
follows the critical path in
[CONTRIBUTING §2](CONTRIBUTING.md#2-how-work-is-picked-up) and each issue's dependency list. A maintainer edits the
"Current focus" line; the rest follows the merged work.

## 0.2: a working engine

**Goal:** a `Revokt` you can build, start and query, with data updated in memory from Mozilla's signed feed.

- **A minimal `Revokt`:** build, a synchronous start that loads a seed and publishes the first data generation, and
  close. There is no durable store yet, and no readiness future or caches.
- **The path walker:** finds and verifies the issuer of the certificate the platform accepted, within fixed budgets,
  so an attacker cannot make it do unbounded work; a chain that exceeds them is rejected. The platform's PKIX builder
  is the fallback. The walker and the `Rule` model get a dedicated adversarial review before the walker is coded, and
  a fuzzer then runs against it with eight properties as a release gate.
- **Mozilla Remote Settings:** the feed protocol, with content-signature verification and x5u certificate-chain
  validation, so tampered data is refused whatever the transport.
- **The CRLite updater in memory:** applies full filters and deltas with coverage checks and rollback protection.
- **Seeds:** a bundled filter for the first launch, and the job that publishes the data artifacts.
- **Cross-engine checks:** a CI-only engine over rustls/upki, compared with revokt's on the same queries.
- **Benchmarks** for the per-handshake cost goal: p95 under 1 ms with a warm JIT and a cached path.

## 0.3: usable in apps

**Goal:** everything an Android or JVM application needs to adopt revokt.

- **A durable store** that survives crashes and is safe between processes, with a lock, plus the C2SP mirror and
  the system cache as bootstrap-only sources.
- **Bindings:** OkHttp, and one adapter per Ktor engine.
- **Per-delegate trust managers** for private CAs, verdict and path caches, the lifecycle state machine and a
  readiness future.
- **Operability:** `OBSERVE` events, `status()` and `state`, to measure a policy before enforcing it.
- **Android:**
  - an instrumented test suite on API 26, 31, 34 and 36;
  - WorkManager periodic sync;
  - a Baseline Profile;
  - a consumer build with AGP 8.5.2.
- **`revokt-testing`:** `FakeRevokt` and the fixtures, for consumers' tests.

## M2: 0.4 → 1.0, intermediates, OneCRL and CRLSets

**Goal:** the remaining browser revocation sources, and the 1.0 compatibility promise.

- **Mozilla's intermediate preload set** as a second source of issuers, closing the Android gap where a server omits
  an intermediate.
- **OneCRL**, including anchors; the bundled denylist; **Chrome CRLSets**.
- **The 1.0 promise:** binary compatibility within a major, under the growability contract. From 1.0, a new rejecting
  rule ships as allow for one minor before it rejects; M2's own OneCRL, CRLSet and denylist rules are the exception,
  as the 0.4 → 1.0 transition.

## M3: Certificate Transparency

CT policy checking from the SCTs in the certificate, with a `CT_UNVERIFIED` rule for what cannot be checked. Both
rules ship as allow in `STRICT` for one minor before they reject there; both stay allow in `DEFAULT`.

## M4: distrust

Per-anchor distrust, evaluated over every path the walker finds.

## M5: Merkle Tree Certificates

Merkle Tree Certificates through `Evaluator.evaluate`, routed by credential type and evaluated by their own seam.
