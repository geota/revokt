- **#222 (audit B-F9), part 2, the path finding:**
  - §4: `Finding.Path` keeps `status`, `source`, one `reason`, `issuerSpkiSha256s` and `anchorSha256`. `reason` is a
    new growable `PathReason`, the union of `NoIssuerReason`, `ParseReason` and the walk's budgets, plus
    `FALLBACK_LIMIT` for a completed `NotFound` over `FALLBACK_MAX_PRESENTED`. It is set exactly for `NO_ISSUER`,
    `PARSE_FAILED` and `PATH_BUDGET_EXCEEDED`, and is a reason of that status.
  - §4: `walkerReason`, `keyabilityClause`, `terminalKind`, `endReason`, `endDepth`, `anchorSnapshotId`,
    `usedFallback`, `pathsFound`, the reported path, `candidatesDropped` and the walk counters move to the
    evaluation's one `DEBUG` line, with the meanings they had. `rewalkEnd` (M2) and `cacheHit` (0.3) join the line
    when built. `Finding.Path.credentialType` is dropped (`ExemptionContext` carries it).
  - §4, §5.1: `platformOnly()` matches `reason == PLATFORM_ONLY`, `outcomeDepended` reads `reason`, and the step-6
    fallback-limit exit is `PATH_BUDGET_EXCEEDED(FALLBACK_LIMIT)`.
  - The test plan reads a walker row's detail fields from the decision, and its reasons as `Finding.Path.reason`.
