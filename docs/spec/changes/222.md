- **#222 (audit B-F9), one failure vocabulary for sync results:**
  - §4: `SyncOutcome` is `INSTALLED`, `UNCHANGED`, `SKIPPED` and `FAILED`. A `SKIPPED` or `FAILED` sync carries one
    growable `SyncFailure` code on `SyncResult.failure`, one code per step a sync can stop at, so `SyncStage` and
    `SyncResult.stage` are removed. `BACKOFF` and `ROLLBACK_REFUSED` are the `SKIPPED` codes. `CLOCK_SKEW`,
    `STORE_FAILED`, the fetch, signature, schema, index, attachment and engine failures are `FAILED` codes. A 401 or
    407 is the code of the fetch it interrupted. `STORE_LOCKED` joins the enum with the store lock.
  - §4: `DiagnosticCode` lists the configuration codes the engine produces. Runtime conditions are a new
    `WarningCode` on a new `RevoktWarning` (code, dataset, message): `SyncResult.warnings` and the seed load carry
    them. `SYNC_FAILED`, `SYNC_SCHEMA_REJECTED`, and `INDEX_INCONSISTENT`, `FORMAT_UNSUPPORTED` and `CAP_NEAR_LIMIT`
    as failures, leave the warnings: why a sync stopped is its `SyncFailure`. A bullet's code joins its enum when its
    producer is built, and each unbuilt bullet's code is assigned to the enum it will join. `RevoktState` carries
    `warnings: List<RevoktWarning>` and `diagnostics: List<PolicyDiagnostic>`.
  - §3, §3.2, §5.1, §5.2, §6.5 and §7.1 name each failure by its code, not by an outcome and a stage. A feed failure
    is any `FAILED` sync; a `SKIPPED` one leaves `consecutiveFailures` unchanged. The Android worker maps `SKIPPED`
    to success and `FAILED` to retry, as before.
  - The test plan's rows name the codes.
