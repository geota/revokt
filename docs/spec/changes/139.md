- **#139:** `Revokt.Builder`, `build()` and `validate()` in revokt-jsse (`dev.revokt.jsse.Revokt`).
  - §4: the Java forms of `sources { }` and `limits { }` are the flat `remoteSettings`, `seed`, `maxFilterBytes`,
    `maxJsonBytes`, `maxX5uBytes` and `maxChangesetRecords`; a later call replaces an earlier one.
  - §4 `channel`: the default `SeedSource.bundled()` counts as a CRLite source, so only `seed(SeedSource.none())`
    with no remote settings builds without a channel. R `CHANNEL_UNSET` is named in `build()`'s message only.
  - §4 source URLs: absolute `https` (any case) with a host, no userinfo, no query or fragment, a port from 1 to
    65535 or none, read by `java.net.URI`, the rule the default fetch path applies (the client joins paths to the
    base and does not run the x5u `StrictUrl` on it). A query or fragment, or an out-of-range port, would build and
    then fail every sync. `build()`'s message names the field and the rule, never the URL or any part of it.
  - §4 `clock`: `kotlin.time.Clock` is stable from Kotlin 2.3. `timeSource` is internal, a test seam.
  - §4 `awaitData`: 2 s on the JVM; the `AWAIT_DATA_<CHANNEL>` constants come with the Android measurement.
  - §4 `validate()`: `validateOrThrow` throws `IllegalStateException` iff any `ERROR`; the order of the diagnostics;
    `revocationEngine.formats` is read once, at `build()`. `pkixFallback` defaults to true.
  - §3.2: an engine goes into one `Revokt` ever, compared by identity; a `build()` that throws registers nothing.
  - §4 `DiagnosticCode` gains the codes whose producer this builds: `CHANNEL_UNSET`,
    `NO_DATA_REJECTS_WITHOUT_LOCAL_DATA`, `NO_REQUIRED_DATASETS`, `IN_MEMORY_STORE_WITH_FETCHING_SOURCE`,
    `FORMAT_UNSUPPORTED`, `NO_FETCHING_SOURCE`, `IO_DISPATCHER_UNCONFINED`.
  - §11 0.2: the builder has no `storage` member; the store is `RevoktStorage.inMemory()`.
