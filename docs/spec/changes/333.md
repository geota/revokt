- **#333, `start()`'s load after the store switch:**
  - §6.5 Load step 4: at `start()` `buildIndex` reads each placed filter's coverage alone (the first field after the
    2-byte prefix in v3 and v4, under §6.3's rules for it), which gives the whole decode's index for every filter that
    decodes; `prepare` is the one decode, and a filter whose coverage reads but whose rest does not decode fails the
    `prepare`, so the chain falls down as for a failed load. The adopt scan decodes every filter whole before it writes
    `updater.json`, and an install decodes every placed filter whole, failing a sync with `FILTER_UNREADABLE` and a
    seed with `SEED_UNREADABLE` before the generation file is written.
  - §6.4: the load columns are measured on ART, emulator lower bounds: `compat` 73 ms cold, 28 ms warm and 190 ms
    interpreted, `default` 86, 51 and 332 ms, with the method stated.
  - test-plan.md §9.1: the coverage-only read is a fuzz target, differential against the whole decode.
