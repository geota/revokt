- **#330, `JvmStorage`'s writes, lock and open:**
  - §3 `RevoktStorage`: a write whose fsync, directory fsync or rename throws throws; on Windows the directory fsync is
    skipped. `JvmStorage`'s `lock()`, once it holds the lock, deletes every temp file under its root, then fsyncs
    every directory under it, the root included, in place of the three named store directories. The parent of every
    directory it creates is fsynced, the root's included.
  - §3 `names()` excludes every entry whose path is not a key; `JvmStorage` lists regular files only and follows no
    link below its root's real path: a link in a key's path makes it not a key, so `names()` skips it and `read()`,
    `write()` and `delete()` of it throw.
  - §3 `identity()` is the absolute normalised directory, computed with no I/O; `JvmStorage.directory(…)` does no I/O,
    and `lock()` creates the directory.
  - §3 `lock()`: `FileChannel.tryLock` on `.lock`, tried every 100 ms for 1 s; one channel per `.lock` in a process,
    so a failed second attempt cannot drop the holder's fcntl lock; the ownership check runs before `.lock` is opened,
    which follows no link and must be a regular file; `.lock` is never deleted; any other failure in `lock()` is
    `STORE_UNREADABLE`.
  - §3 the ownership check compares the directory's uid with a probe file's, and is skipped without a unix view.
  - §3 Windows: the rename over an open `current` is retried for up to 1 s, then the write throws.
  - §6.5 temp files: the key's last segment, `~` and 32 random hex digits, with no pid; `~` keeps them out of the key
    space. No link below the store's real root is followed.
  - test-plan.md (e): the `JvmStorage` row names `JvmStorageTest` and `JvmStorageContractTest`.
