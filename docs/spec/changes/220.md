- **#220 (audit B-F6):** the `RevocationEngine` seam is internal, and the per-install self-check moves to the
  cross-engine suite.
  - §3.1 and §3.2: `RevocationEngine`, `PreparedGeneration`, `KotlinRevocationEngine` and
    `Revokt.Builder.revocationEngine` are `@RevoktInternalApi`, for revokt's own tests and the CI-only upki engine;
    publishing the seam is revisited only if a real second engine appears. §4 drops `KotlinRevocationEngine()` from
    the public service types, and V `FORMAT_UNSUPPORTED` now fires only for another engine injected through the
    internal seam.
  - §6.5: the install no longer runs the engine self-check between `prepare` and `activate`, and no longer decodes
    the filters itself: `engine.prepare` is the install's only decode. §4 drops `SyncStage.SELF_CHECK` and
    `DiagnosticCode.ENGINE_SELF_CHECK_FAILED`; §4 S, §5.1 and §5.5 drop the self-check from the seed path, the
    `close()` wait and the interrupt rule.
  - Test plan §9.3: the probes the self-check ran are the cross-engine suite's engine probes, run on each engine's
    prepared generation in CI, with the same named inputs; the Kotlin engine runs them in `check`.
