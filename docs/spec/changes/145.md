- **#145 (the seed writer and the data/seed build):**
  - **The maintainer's decision (2026-11-23): in 0.2 a seed is a GitHub release asset with attestations, not on Maven
    Central.** #149 attaches it, and an app bundles the `revokt-seed-<channel>` jar itself so that
    `SeedSource.bundled()` resolves it. Maven publishing, with its separate namespace and Portal account, is a later
    decision. This touches §3 (the module table, licensing), §6.5, §7.2, §11's 0.2 row, §13 item 5 and CONTRIBUTING
    §3 and §9.
  - §6.5 "Seed archive", the writer side: `buildSeed` and `SeedJob`, internal code in revokt-engine. They ship in the
    `revokt-engine-jvm` jar, and only an explicit call reaches them. The job's entry (data/seed) ships nowhere.
    - Entry order: `seed.json`, `records.json`, `signature`, `x5u.pem`, `index.bin`, then `attachments/<f>` in
      placement order.
    - `seed.json` is stored (the reader still accepts it deflated), and every other entry is raw deflate at level 9.
    - Every entry is dated 1980-02-01 00:00, with no extra field, comment or data descriptor.
    - `seed.json` is compact JSON, and its `filterFormat` is the full filter's decoded encoding. A delta may be in
      another encoding the engine lists, and only an encoding the engine does not list is refused. This follows the
      maintainer's #137 decision, as the sync and the loader do.
    - The job verifies as a sync verifies the whole collection, loads the archive once from memory under the source's
      pins, and only then writes it through a temporary file.
    - Archive bytes are fixed for one changeset on the same Temurin 21 build: the deflate output is that JDK's zlib's.
      The build asks for Temurin 21, and #149's job pins the exact build through its setup-java version.
    - The signed `<ts>` must also be no older than the default CRLite `staleAfter` (3 days) before the version day: an
      older changeset means a frozen source or a wrong version. #149 adds the monotonic check against the last
      release's `<ts>`.
  - §7.2 "Data artifacts":
    - `YYYY.MM.DD` is the run's UTC date (`-Prevokt.seedVersion`). The signed `<ts>` must not be after it, nor more
      than 3 days before it.
    - "No build-time plugin" means none for a consumer: `data-artifact` is revokt's own build's.
    - A seed jar holds only the manifest, `META-INF/LICENSE-DATA` and the stored `/revokt/seed-<channel>.zip`.
  - §3: the data licence text travels in the seed jar, as the manifest's `Revokt-Data-License` and as
    `META-INF/LICENSE-DATA`. There is no POM, so `verifyPomLicenses` is unchanged.
