- **#145 (the seed writer and the data/seed build):**
  - §6.5 "Seed archive": the writer side. `buildSeed` and `SeedJob` (internal to revokt-engine) write the entries in
    the order `seed.json`, `records.json`, `signature`, `x5u.pem`, `index.bin`, then `attachments/<f>` in placement
    order. `seed.json` is stored (the reader still accepts it deflated), and every other entry is raw deflate at level 9.
    Every entry is dated 1980-02-01 00:00, with no extra field, comment or data descriptor. `seed.json` is compact JSON,
    and its `filterFormat` is the full filter's decoded encoding; a delta may be in another encoding the engine lists.
    The job verifies as a sync verifies the whole collection, then loads the archive once from memory under the
    source's pins, and only then writes it through a temporary file. Archive bytes are fixed for one changeset on one
    JDK build: the deflate output is that JDK's zlib's, and the job pins Temurin 21.
  - §7.2 "Data artifacts": `YYYY.MM.DD` is the run's UTC date (`-Prevokt.seedVersion`), and the signed `<ts>` must not
    be after it. "No build-time plugin" means none for a consumer: `data-artifact` is revokt's own build's.
  - §7.2: a seed jar holds only the manifest and the stored `/revokt/seed-<channel>.zip`. Its POM has no dependency and
    carries the data licence, and no Gradle module metadata is published.
  - §3: `verifyPomLicenses` accepts the data licence text only on the data artifacts' coordinates, as each POM states
    them: `dev.revokt` (a placeholder until the data namespace is decided) and the closed set `revokt-seed-compat`,
    `revokt-seed-default`.
