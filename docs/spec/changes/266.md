- **#266 (audit B-F12, phase 2 of #228):** the updater, the Remote Settings client, the store and the seed loader move
  from `revokt-engine`'s commonMain to jvmMain, so the native compile checks only the common parts.
  - §3: the module table moves the updater state machine and sync, the Remote Settings protocol and
    `MozillaRemoteSettings`, the `RevoktStorage` interface with `inMemory()` and the store layout, the seed loader and
    archive reader, and `SeedSource` to the jvmMain row. `SeedSource` is a plain JVM class with `none`, `of`,
    `fromResource` and `bundled`. The expect/actual pairs of `SeedSource`, the raw inflater, the fetch timeout and the
    in-memory store's lock are gone. The generation snapshot the rules read stays common.
  - §3 "Purity gate": the walker and `verify/` stay common, and the pairs left (`lruMap`, `isFatal` and
    `restoreInterrupt`, `canonicalSubject`) exist so that the native compile covers the walker and the
    content-signature and x5u logic. `LruMap` is an internal interface made by `expect fun lruMap`, so commonMain has
    no expect class.
  - §4: the `SeedSource` sketch is marked jvmMain.
