- **#128:** §4's `JdkHttpFetcher` comment states the rest of the JDK fetcher's transport rules.
  - It sends `Accept-Encoding: gzip`, whatever the request's headers say, and inflates under `maxBodyBytes`. It drops
    `Content-Encoding` and `Content-Length` from the response it returns, and any other `Content-Encoding` throws. §3's
    `FetchRequest` says that a fetcher that inflates sets `Accept-Encoding` itself.
  - It uses `setUseCaches(false)` and fetches over https only.
  - Every handshake runs over `HttpsURLConnection.getDefaultSSLSocketFactory()`, read at each fetch, with endpoint
    identification `HTTPS` set on each socket. A global default hostname verifier therefore cannot turn the check off.
  - `timeoutMillis` is its connect and read timeout. An interrupt seen before connecting or between body reads
    disconnects and throws, and no connection outlives its fetch.
  - A JVM default `CookieHandler` and the JDK's transparent Negotiate or NTLM answer to a 401 have no per-connection
    switch, and are stated as residuals.
