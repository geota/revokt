- **#321:** §9.1 Harness raises `-rss_limit_mb` from 1024 to 2560, ClusterFuzz's libFuzzer default (OSS-Fuzz's
  2.5 GB per-input limit), which Jazzer targets run under: the test JVM's own footprint (1.1 to 1.8 GB with the heap
  capped at `-Xmx256m`) went over 1024, for several targets before any input ran, so 8 targets a night failed as
  out-of-memory. `-Xmx256m` stays the bound on what one input can allocate on the heap. §9.1 Findings: a nightly
  failure is a finding only when its saved input, replayed alone under the harness, fails again (one attempt; any
  non-zero exit) and the empty input passes, a control against systematic failures; anything else fails the run
  without filing an advisory.
